## Findings, in priority order

### A1 — Moderate: the Stage 5 prose sometimes turns a result about cβ into a result about c

Locations: `REPORT.md:581-592`, the P18/P19 wording at `REPORT.md:617-618`, and `README.md:31-34`. The underlying grading definitions are in `PREREGISTRATION.md:535-539`.

The report correctly derives and repeatedly explains that equation (4.2) identifies **x = cβ**, not c. Nevertheless, it says that the Ulysses half of Simon's sentence holds, that the ordering **c(Ulysses) > c(Eldridge)** holds, and, in the README, that Eldridge gives **c ≈ 0**. These conclusions do not follow without an additional restriction on β.

A concrete counterexample using the fitted values: T2 has x = 0.161907443, compatible with c = 0.2 and β = 0.809537215. Eldridge has x = 0.020513840, compatible with c = 0.5 and β = 0.041027680. Both obey the parameter ranges and produce exactly the same fitted distributions, while their c values have the **opposite** ordering. Likewise, a small x does not identify a small c.

Smallest correction: consistently say **x(Ulysses) > x(Eldridge)** and **x(Eldridge) ≈ 0.02**. Describe the fitted products as compatible with Simon's proposed c values for suitable β, without claiming to identify those values. Retain the frozen P18/P19 outcomes, but label them as outcomes of the preregistered **product-based proxy**. The later caveat is good; it should also constrain the affirmative claims above it.

### A2 — Moderate: distinguish failure to detect an improvement from model adequacy

Locations: `src/stage4.py:383`; `results/stage4-verdicts.md:49,61-62`; associated grading language at `REPORT.md:416-430,581-588,619-626`.

The nested-model comparison prints **“Yule adequate”** whenever the likelihood-ratio comparison is nonsignificant. That test only asks whether the added model parameter improves the fit. It does not establish absolute adequacy. The table itself demonstrates the problem: Eldridge's cutoff comparison says “Yule adequate” at LR p = 0.25, while the Yule goodness-of-fit p is 0.006. Econometrica has the same contradiction for both nested comparisons.

Smallest correction: replace that comparison label with **“no significant improvement over Yule”**. Keep the separate goodness-of-fit column.

The Stage 4 headline is defensible as a description of the frozen criterion, but its scope should remain explicit: it is an **iid parametric-bootstrap test of newly fitted Yule distributions**, with each sample containing n independent type sizes. It is not a direct test of Simon's printed estimates, a calibrated test of his dependent growth process, or a unique mathematical definition of his qualitative “reasonably good.” Stage 3 addresses a different, process-based question.

Suggested headline: **“The refitted Yule is rejected at 5% by the preregistered 11-cell test for three of the four Table 3 datasets.”** For Physicists, say “not rejected by X²; rejected by the supplementary KS test.” For P20, say “Eldridge is rejected; none of the three recounts is rejected by the pooled 11-cell test.” Both prediction verdicts remain unchanged. A high p-value does not establish model truth or practical adequacy; see the [ASA statement, principles 2, 5 and 6](https://doi.org/10.1080/00031305.2016.1154108).

### A3 — Moderate: zero bootstrap exceedances do not establish p < 1/500

Locations: `REPORT.md:423,437,453,575`; the `0.000` bootstrap entries in `results/stage4-verdicts.md`. The code and contract explicitly use the exceedance fraction, so the stored zero is faithful to that convention.

The Chem result is **0 exceedances out of 500**. Reporting this as an estimated fraction of zero is understandable if labeled, but the P13 row's **“p < 1/500”** reads as a bound on the underlying bootstrap probability. That bound is not supported by 500 draws. With 0/500, the exact one-sided 95% binomial upper bound is approximately **0.00597**; the two-sided 95% interval is **[0, 0.00735]**. The 5% rejection is secure, but the stronger numerical bound is not.

Smallest correction: print **“0/500 exceedances”** and explain the Monte Carlo resolution. Preserve the historical raw fractions. If adopting a nonzero reporting convention such as (b+1)/(B+1), document that separately rather than silently changing the preregistration.

Physicists' original 32/500 = 0.064 also deserves a Monte Carlo qualifier: its exact 95% simulation interval is **[0.0442, 0.0892]**, crossing 0.05. I resolved this concern with a separately labeled supplemental check: **711/10,000 = 0.0711**, interval **[0.0661, 0.0763]**, using an independent implementation, an exact beta-geometric Yule sampler, and a refit in every replicate. This supports the original non-rejection; it does not replace the frozen run or turn non-rejection into proof of good fit. These intervals measure simulation error conditional on the fitted null, not uncertainty in whether the model is true.

### A4 — Minor: the standalone Table 3 figure mislabels Chicago's recipe

Locations: `src/stage6.py:35`, `results/stage6-table3.png/.svg`; the correct exception appears only in `REPORT.md:698-701`.

The common legend says **“recipe (α = n/k)”**, but Chicago uses ρ̄ = 133/145 and starts from observed f(1). It does not use α = 278/1124. The numerical series is correct, and the report explains the exception, but the image alone asserts the wrong estimator for one panel.

Smallest correction: use “stated recipe” in the common legend and add a figure footnote identifying Chicago's ρ̄ exception. The same footnote can identify Econometrica f(10) = 0, which cannot appear on the log count axis and has no defined estimate/observed ratio. The separated 11+ points are handled correctly. In Table 2, specifying the MLE censor points (Hanley at 4+, Eldridge at 11+) would also help readers.

### 4. P7a and P20: correctly marked failed

The ENB advantage is **66.629427**, so the prediction unequivocally fails under its AIC rule. The explanation is mathematically reasonable: for fixed θ < 1, the exponential factor eventually dominates the power factor.
